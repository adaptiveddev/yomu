# Work in progress — not a release

Based on 2.0.4. Version numbers are intentionally unchanged. Do not distribute this tree as a finished build.

## Implemented in this work
- Prototype fixed-layout EPUB rendering: honors package and spine layout, scales original viewport, image spine items, avoids detecting fixed layout as image-only manga. Existing imported entries marked manga are not migrated automatically. Verify on real books and Android WebView, in particular script restrictions, spreads, rotation and navigation.
- PDF reflow paragraph handling and original-page preview for image/empty/failing extraction. This is not graphical reflow; columns, tables and images need substantial further work.
- Tracker link sync in a separate bounded sidecar (strong ETags on WebDAV, best-effort change detection in shared folders); three-way merge, unknown entries preserved, absent books are not deletion, conflicts and pending changes protected, missing file after a known base fails closed. No tokens, account-specific library IDs, scores or progress leave the device. Imported entries must be refreshed from the account first; a local sentinel prevents default state from being pushed, and the UI marks it. Does not support stable identity for image folders.

## Not finished
- Image folders, edits, cross-device deletions and safe identity migration of metadata/annotations/tracker links remain unfinished. File copies are opt-in on WebDAV and shared-folder SAF; local deletions after a successful sync are suppressed on that device, not propagated. SAF does not offer WebDAV-style compare-and-swap.
- Kitsu is experimental (see below); MangaUpdates and other trackers are not implemented. Their live authentication/API behavior and rate limits require validation; credentials/tokens must remain private.
- Complex Word rendering and complete PDF reflow remain incomplete. DRM depends on vendor, licensing and a supported SDK; no universal DRM support claimed.
- Verify on real Android device and real WebDAV/server/tracker accounts; emulator in this environment did not boot. Also test real publisher EPUB/PDF/DOCX fixtures, upgrades/backward compatibility and original reader features.
- Build and sign APK, package sources, run all tests/lint and update release docs only when ready.

## Additional safety work (2026-11-06)
- The main WebDAV sync file now requires a strong ETag; absent or weak tags fail closed instead of performing unconditional overwrites. The two sidecar transports also validate supplied tags.
- Shared-folder metadata sync no longer treats failed listings as empty, rejects duplicate names, detects changes visible before a write, and explains that SAF/cloud storage offers no atomic compare-and-swap. File transfer and tracking sidecars were added later (see below); image-folder transfer is still not implemented.
- Local merge-base writes use AtomicFile; corrupted/incomplete bases fail closed, and a previously synced remote metadata file missing from the same target is not silently recreated. Restoring a backup clears both metadata and tracker-link bases to avoid interpreting restored missing links as intentional remote deletions.
- Metadata merge and server write share a database transaction, so a detected conflict or failed write rolls back the local merge. Book-file import remains a separate operation. An accepted server write followed by a lost response requires retry/merge on the next sync.
- Latest full `testDebugUnitTest --continue`: 291 passed, 1 skipped, 0 failures (62 suites). Includes three folder-provider, four base-safety, and three merge/write transaction tests. These are automated tests, not real-device or real-cloud tests.

## Stage 1 sync completion (2026-11-08)
- Conflicts no longer end in a single error line: sync problems are recorded per item (kind, subject, detail, target) in `filesDir/sync/problems.json`, and Settings → Sync opens a conflicts screen listing them with dismiss/clear. Raising a problem still never deletes or overwrites data.
- Changed regular book files are adoptable: a changed file stops only that book's file part and is recorded; "Keep my version" re-registers the content under its new identity (new blob, re-keyed metadata/bases/index, replacement marker old→current with collapsed chains, durable journal, crash-resumable). Repeats — including Yomu's own PDF annotation writes, recognized via the annotation manifest and adopted automatically — are cheap marker updates. "Take the other version" replaces the local file, keeping bookId and records. A file changed on both devices is a recorded conflict until resolved.
- Legacy (`dir:`) image folders migrate to stable identities from the same screen ("Migrate to a stable identity"): shared metadata v3 revisions, folder index (with replacement markers), merge bases, position baseline rows and the book row are rewritten under a durable journal; other devices follow the marker automatically instead of creating a second copy, and refuse when their pages diverged.
- Image-folder page changes no longer abort everything: an ambiguous folder is skipped with a recorded problem while the rest syncs. "Publish my version" / "Accept the other version" commit explicitly, remapping unambiguous positions, restarting the reading position on a changed/removed page and keeping annotations in place (dangling, reported) — nothing is silently dropped.
- Book removals propagate as verified deletion markers (expected shared fingerprints + time, 180-day horizon): an unchanged copy is removed with its records and the library's own file; a copy changed since the last sync is kept with a recorded `book_deletion_conflict`; deletions off keep everything local. Per-book baselines (shared + private fingerprints) are captured after every successful sync. Server blobs are never deleted; folders are not covered by deletion markers.
- Local base stores now publish via verified temp+move (AtomicPublish) instead of AtomicFile, which cannot overwrite an existing file on Windows hosts — device behavior is unchanged, and host test runs now exercise the same paths.
- New/updated tests: SyncProblemsTest, BookAdoption{Follow,Conflict,Pdf,Journal}Test, SyncIdentityMigrationTest, FolderMigrationTest, FolderPageChangesTest, BookDeletionSyncTest; BookFileSync/FolderSync/FolderManifest tests updated to the new semantics.
- Automated verification of this stage: full `:data:testDebugUnitTest` green except 3 pre-existing LocalBookBackupTest failures that reproduce on the pristine snapshot of this Windows host (backup ZIP entries built with backslash paths); `:feature:settings:compileDebugKotlin`, `:data:lintDebug`, `:feature:settings:lintDebug` passed (see the final checkpoint below for the exact commands and counts).
- Not verified on real devices/WebDAV/shared folders; no accounts, no real two-library exchange outside simulated transports. The four remaining LocalBookBackupTest failures are host-only and must be confirmed on Linux CI.

## Shared-folder transfer and local deletion protection (2026-11-07)
- FolderSyncBackend implements file and tracker-link sidecars. Blob uploads use a random staged document, verify SHA-256 and length, then rename and verify again; providers without rename fail without publishing a manifest. Indexes detect changes visible before writing; neither this nor rename is an atomic cross-device CAS. Sync one device at a time and do not rely on providers with delayed visibility.
- A target-specific AtomicFile records the local file identities after successful file sync. Books removed from this device later are not re-imported here; manual re-import clears suppression. This does not delete remote blobs or books on other devices. Restore clears this base; existing installations gain protection only after their first successful sync. A missing previously known manifest fails closed.
- Two simulated libraries exchanged a text book through a fake SAF provider; targeted tests cover corruption, duplicate/conflict, rename failure, local removal, re-add and reset. Full `testDebugUnitTest :domain:test --continue`: 368 passed, 1 skipped, 0 failures (74 suites). `:app:compileDebugKotlin` passed. No real Android or cloud-provider testing has been performed.
- `:data:lintDebug :feature:settings:lintDebug` passed. This is module lint only, not full-app lint or device testing.

## WebDAV safety checkpoint (2026-11-07; still stage 1 WIP)

- ETags for all WebDAV sync documents must be a single valid strong quoted entity-tag. Wildcards, weak tags, lists and unquoted values are rejected before conditional writes.
- Added simulated interrupted-download and lost-upload-response retry tests, as well as a successful PUT with corrupt stored data and invalid-ETag tests. These are automated tests, not live-server validation.

## Shared-folder and import safety checkpoint (2026-11-07; stage 1 still incomplete)
- Shared-folder metadata and sidecar writes now stage and verify new bytes, rename an existing file to a uniquely named recovery copy, publish and verify the new file, then remove the recovery copy. A remaining recovery copy blocks subsequent reads/writes for that file; follow the recovery guidance in the user guide. The provider must support rename; simultaneous or delayed-visibility SAF writes remain unsafe. Only fake-provider tests have been run.

## Folder-transfer groundwork (2026-11-07; not enabled)
- Added an experimental image-folder manifest, bounded path validation, snapshot and verified blob transfer, revision comparison, and atomic local position remapping. Prototype two-library tests cover file and tracker-link transfers, folder updates and conflicts. The experimental coordinator is **not connected to the sync manager**, and normal users cannot yet synchronize image folders with it.
- Position mapping rejects removed or ambiguous referenced pages. A separate pure transform is tested for translating explicitly revision-qualified remote progress, highlights, notes and bookmarks. The implementation must fail closed on unsafe concurrent changes and must not silently delete remote blobs.
- On the active file-sync path, modified local books and duplicate local or remote identities are reported as conflicts without replacing files or silently merging records. File-identity migration remains unfinished.

A reused page filename that contains a different old image now raises a conflict instead of silently mapping a saved position to the wrong page.

## Integrated folder synchronization checkpoint (2026-11-07; stage 1 still incomplete)

### Дополнительная проверка первого этапа (WIP)

- Переходы к закладкам, заметкам, выделениям и словам передают ссылку на запись, а не полагаются на старую копию номера страницы: после получения блокировки ридера позиция читается заново. Устаревший маршрут без ссылки для стабильной папки не принимается. При асинхронном закрытии предыдущего ридера новый ограниченное время ждёт фактического освобождения блокировки.
- Перед публикацией индекса папок проверяются локальные сохранённые позиции; при отсутствии исходной локальной версии страниц синхронизация останавливается и не выдумывает её из текущего содержимого. Окончательная проверка повторяется при транзакционном применении. Предварительная проверка не делает раздельные файлы синхронизации единой атомарной транзакцией.
- Полноценные перенос ранее импортированных папок, разрешение совпадающих независимых папок и передача удалений книг ещё не реализованы. Проверок реальных WebDAV и Android-устройств нет; первый этап не завершён.

- Предварительная проверка сопоставления позиций включает снимок метаданных с сервера, включая закладки других устройств. Смена содержимого сохранённой страницы при прежнем имени считается неоднозначной, а не автоматически исправленной страницей. Это не устраняет гонку между независимыми файлами и не заменяет интерфейс разрешения конфликтов.

- При повторном ручном импорте ранее удалённой папки обнаруживается совпадение с её старой общей копией и синхронизация останавливается до выбора способа объединения. Автоматическое восстановление старой привязки папки пока не реализовано; записи и файлы не объединяются по одному совпадающему названию или изображению.

- Проверен моделируемый обрыв загрузки страницы папки и обрыв скачивания с последующим повтором: индекс не ссылается на незавершённую загрузку, частичная папка не импортируется. Основные конфликты папок при ручной синхронизации выводятся на русском и английском; это не интерфейс их разрешения.

### Защита удаления аннотаций (экспериментальная, уточнение предыдущего предупреждения)

- Для выделений, заметок и закладок в общей записи сохраняется доказательство версии удаляемой аннотации; локальная база хранит подтверждённые отпечатки. При несовпадении версий, отсутствии доказательства у старого маркера или неопределённой базе слияние останавливается до удаления. Избранное и привязанные локальные заметки выделения защищены от удаления с другого устройства. Локальные отпечатки и содержимое локальных заметок не отправляются. Проверены моделируемые конкурирующие изменения, неверные часы и полный путь через менеджер синхронизации.
- Старые версии могут игнорировать или удалять новые поля. Все устройства, работающие с одной целью, должны быть обновлены; автоматического разрешения конфликтов и подтверждения на реальных устройствах нет. Проверка ещё не распространяется на удаление книг, слов и онлайн-записей. Одновременные изменения одной аннотации теперь обнаруживаются сравнением с общей сохранённой версией, а односторонние правки переносятся независимо от часов устройства; при неоднозначности синхронизация останавливается. Раздельные файлы синхронизации по-прежнему не являются единой транзакцией и требуют дальнейшей работы. Пока настройку синхронизации удалений для важных данных безопаснее выключить.
